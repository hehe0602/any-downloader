## 3. 已实锤的结论（别再重复踩）

用**用户真实会话**（`会话数据/` 里的 WebView2 配置）实测，方法见开发文档 11.6：

| 实测项 | 结果 |
|---|---|
| `pan.quark.cn/account/info` + 会话 Cookie | 200，返回昵称（说明 Cookie 有效） |
| `drive-pc.quark.cn/1/clouddrive/member` + Cookie | `code=0`，`member_type=NORMAL`，含 `use_capacity/total_capacity` |
| 同接口**不带** Cookie | `401` + `31001 require login [guest]` |
| 自有文件 `file/download`（1MB jpg、45.4MB mp4） | `code=0` + `download_url` |
| 分享文件**小**（775B）直签 | `code=0` + `download_url` |
| 分享文件**大**（2026-11-07：248MB 真机 A/B） | **用 Edge UA → `23018 download file size limit`；用 PC 客户端 UA → `code=0` + 直链**。同一组 Cookie、同一个文件，只差 UA |
| 签出的分享直链 `Range: bytes=0-1023` | 用**新的** `__puus` → `206`；用**过期** `__puus` → `412` / `403 RequestDeniedByCallback`（列表接口不受影响） |
| `auth/pc/flush`（票据刷新） | `code=0`，Set-Cookie 下发新的 `__puus`；用 `__pus` 换，刷新失败不影响原 Cookie |
| `sharepage/save`（转存，历史） | 返回 `task_id`，随后任务报 `32003 capacity limit`；**该代码已于 2026-11-07 删除，不要再加回来** |

三条重要判断：

1. **`23018` + 文案含"游客" = 服务端没把这轮请求认成已登录客户端**：要么 Cookie/票据没带上，
   要么 UA 是浏览器 UA。别再照着错误文案改代码（踩过两次：第一次怪 Cookie，第二次怪"大文件"）。
2. **直链大小从来不是限制**：CDN 只验签名；LinkSwift 用同一套接口 + PC 客户端 UA 能签 12GB，
   实测 248MB 也能签。
3. **不需要转存**：用户明确确认浏览器里的 LinkSwift 也不转存。转存只会往用户网盘写副本，
   账号容量不足（本机 `use_capacity` 11.2GB / `total_capacity` 10GB）时必失败。

## 4. 未验证 / 风险清单（接手先看）

1. **会话 Cookie 会真的过期**：内置 WebView2 里的 `__pus/__puus` 到期后会被浏览器清掉
   （本次排查时这台机器的登录态就是这样失效的）。此时 `capture()` 读不到登录 Cookie，
   列表还能以游客身份看，但签发必然 23018 → 现在会抛 `LoginRequiredError` 自动弹登录窗。
   **只能让用户重新扫码一次**；登录后 `__puus` 会由 `cookie_refresh` 自动续期。
2. **UC 网盘没有做同样的 UA / 票据刷新验证**：`UcParser` 与夸克同构，但它的 `_client()`
   仍用 `ctx.user_agent`（浏览器 UA），且 `sites.py` 里没配 `cookie_refresh`。
   如果 UC 也出现「小文件能下、大文件 23018」或「直链 412」，照夸克的做法改：
   `_client()` 固定 `API_UA` + 在 `SITES["uc"]["cookie_refresh"]` 配
   `https://pc-api.uc.cn/1/clouddrive/auth/pc/flush`（`pr=UCBrowser`，本项目未实测）。
3. **登录态仍是启发式判断**（标志 Cookie 名）。站点换 Cookie 名时 `logged_in` 会变 false，
   但闸门已放宽（有 Cookie 就放行），不会再把用户挡在外面 —— 只是 `sessionHint` 文案会变。
4. **前端轮询**：`startLoginWatch()` 每 2.5s 调一次 `session_state`（只读 Cookie、不发网络请求），
   面板离开 `need_login` 就停；若觉得费，可改成 5s 或只在窗口获得焦点时轮询。
5. **会话 Cookie 是 App-Bound 加密的**：Python 侧解不开，测试必须走 WebView2（开发文档 11.6）。
   排查时可以直接看 `会话数据/EBWebView/Default/Network/Cookies` 这个 SQLite 库：
   **`host_key / name / path / 过期时间` 是明文，只有 `encrypted_value` 是密文** ——
   想知道"到底有没有 `__pus`、父域 Cookie 在不在"，用 sqlite3 查这一张表就够了，不用解密。
6. **别在测试里调 `api.clear_session()`**：它历史上会清空整个配置目录的 Cookie（已修，
   但别拿它做"清零"手段），清掉后用户要重新扫码。
7. `pywebview` 升级到 7.x 前，务必重跑一遍会话取 Cookie（它依赖内部结构 `EdgeChrome.url`，
   已做多层兜底但会退化成"按窗口当前 URL 取"）。
8. **百度 `sharedownload` 未真机复验**：本机 WebView2 里没有 `BDUSS`（只有 BAIDUID 等匿名
   Cookie），所以登录态签发只能按 LinkSwift 2026 / baiduwp 的字段对齐 + `tests/test_baidu.py`
   的 MockTransport 覆盖。拿到真实登录会话后，第一件事是粘贴一条百度分享 → 勾选文件 →
   开始下载，确认 `sharedownload` 回 `errno=0`、`list[0].dlink` 非空、`Range: 0-1` 为 206。
   若回 `9019` 是登录态问题；回 `-20` 是风控；回 `118` 是 sekey/提取码。
9. **百度非 SVIP 是账号级限速**：64 并发对百度不会叠加提速，这是百度策略，不要误判成
   引擎 bug；只有 SVIP 账号能按账号速度跑。

## 5. 代码地图（这次改动相关）

```
app/session.py
  _cookie_backends()       ← 取 Cookie 要改的两个后端对象（EdgeChrome 优先）
  _candidate_urls()        ← 一轮要查哪些 URL
  _read_raw_cookies()      ← 独立线程 + 单次加锁，一次读完所有候选 URL 并取并集
  _collect()               ← 拼 Cookie 头（按目标 URL 过滤）+ 判登录（用未过滤的名字集合）
  capture() / state()      ← 对外的两个入口（capture 带 UA；capture 还会刷新 __puus）
  _ensure_on_site()        ← 隐藏读取窗被劫持/重定向时拉回首页
  _delete_site_cookies()   ← 按域名删 Cookie（UI 线程 + CookieManager）
app/sites.py               ← 站点表：域名 / 登录 URL / Referer / login_cookies / cookie_refresh
app/cookie_refresh.py      ← 短时效票据 __puus 刷新（refresh_cookie / arefresh_cookie / merge_set_cookie）
app/manager.py
  _needs_login()           ← 唯一的"要不要让用户登录"判断
  _add_share()             ← 分享任务：复查会话 → 签发直链 → 每个文件建任务（用 ctx.cookie）
app/parsers/quark.py
  _client()                ← 固定 PC 客户端 UA（浏览器 UA 会触发 23018！）
  issue_direct_urls()      ← 先刷新 __puus，再分批直签（**没有转存**）
  _sign()                  ← file/download（分享 fid 带 pwd_id/stoken/token，自有 fid 不带）
app/parsers/baidu.py
  _extract_token()         ← /s/1<token> 的完整 token（含开头 1，wxlist 要这个口径）
  _wxlist_all()            ← /share/wxlist 翻页列目录 + 提取码校验（mispwd-9）
  _to_share_file()         ← 文件夹 key = 绝对路径（wxlist 的 dir 收路径，不收 fs_id）
  issue_direct_urls()      ← gettemplatevariable → tplconfig → sharedownload；112/118 重试
  _resolve_dlink()         ← dlink 302 预解析成最终 CDN 地址
  _DOWNLOAD_VARIANTS       ← clienttype/UA/type 三套口径（2/113 时轮换）
web/app.js
  refreshSession()         ← 返回 state；未登录→已登录时自动重解析
  startLoginWatch() / stopLoginWatch()   ← 登录引导面板的轮询
  submitForm()             ← need_login 时先复查会话
web/index.html             ← 分享面板的 `share.message` 展示
docs/开发文档.md 4.7 / 6.4 / 11.6 / 13   ← 这次的"为什么这么做"都在这里
```
